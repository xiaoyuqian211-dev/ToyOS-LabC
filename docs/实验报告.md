# ToyOS-LabC 实验报告

## 1. 实验目的

本实验从零实现一个运行在 RISC-V 64 位 QEMU virt 平台上的教学型小操作系统 ToyOS-LabC。实验目标不是复刻完整 Linux，而是通过较小规模的代码贯通操作系统核心机制：启动入口、链接地址、内核串口输出、trap 与系统调用、页式内存管理、进程管理、上下文切换、用户程序执行和简单文件系统。

通过该实验，需要理解以下问题：

- CPU 从固件进入内核后，内核如何建立自己的运行环境。
- 用户态如何通过 `ecall` 进入内核，内核如何保存现场并返回用户态。
- 虚拟地址、物理地址、页表项权限和用户态/内核态隔离之间的关系。
- 进程的 trapframe、内核栈、用户页表和上下文切换如何配合。
- 文件系统如何把“路径”和“字节内容”抽象为系统调用接口。

## 2. 实验环境

目标运行环境：

```text
架构：RISC-V 64
机器：qemu-system-riscv64 virt
固件：OpenSBI，QEMU -bios default
内核模式：Supervisor Mode
内存：128 MiB
工具链：riscv64-linux-gnu-gcc 或 riscv64-unknown-elf-gcc
```

推荐 Ubuntu/WSL2 安装命令：

```sh

```

## 3. 系统总体架构

ToyOS-LabC 按内核、用户程序、公共头文件和脚本分层：

- `include/`：定义基本类型、页表位、内存布局、系统调用号、进程结构和跨模块声明。
- `kernel/`：实现启动入口、链接脚本、控制台、printf、trap、syscall、内存管理、进程管理、ToyFS 和调度。
- `user/`：实现用户态入口、系统调用封装、简化用户库和多个用户程序。
- `scripts/`：提供环境检查、运行 QEMU 和冒烟测试脚本。

内核启动后初始化 console、trap、物理页分配器、内核页表、进程表和 ToyFS，然后创建第一个用户进程 `init`。`init` 通过 `exec("sh")` 进入 shell，shell 自动执行 `hello`、`forkdemo`、`cat` 等命令，覆盖系统调用、进程和文件系统测试。

## 4. 启动流程设计

内核入口为 `kernel/entry.S`，链接脚本为 `kernel/linker.ld`。QEMU virt 使用 OpenSBI 时，内核按 ELF 加载到 `0x80200000`。入口代码完成两件事：

1. 初始化 `gp`，使 RISC-V 小数据区寻址可用。
2. 设置早期启动栈 `boot_stack_top`，然后调用 `kmain`。

`kmain` 位于 `kernel/main.c`，按顺序执行：

```text
console_init
trapinit
kinit
kvminit / kvminithart
timer_init
procinit
fs_init
userinit
scheduler
```

链接脚本明确 `.text`、`.rodata`、`.data`、`.bss` 的布局，并导出 `end` 符号。物理页分配器从 `end` 之后开始回收空闲页，避免覆盖内核镜像。

## 5. 控制台输出与 printf 实现

控制台使用 QEMU virt 的 16550 UART，基地址为 `0x10000000`。`console_putchar` 轮询 UART LSR 寄存器的发送空位，然后写入 THR 寄存器。换行时额外输出 `\r`，保证串口终端显示正常。

`kernel/printf.c` 实现了简化版 `printf`，支持：

```text
%s %d %x %p %c %%
```

`panic` 会打印 `[ToyOS] panic:` 前缀和错误信息，然后进入 `wfi` 循环停机。该实现足够支持内核初始化日志、异常信息、进程表和文件系统测试输出。

## 6. Trap 与系统调用机制

trap 入口在 `kernel/trap.S`。ToyOS 的用户页表会把内核高地址区域映射为 supervisor-only，因此用户态执行 `ecall` 后，CPU 能够在当前用户页表下取到 `trap_entry` 指令，但用户态无法访问这些内核页。

trap 入口流程：

1. 使用 `sscratch` 和 `sp` 交换，取得当前进程的 `trapframe`。
2. 保存通用寄存器、`sepc` 和 `sstatus`。
3. 切换到内核页表 `kernel_satp`。
4. 切换到当前进程的内核栈。
5. 调用 `trap_dispatch`。

`trap_dispatch` 根据 `scause` 区分：

- 用户系统调用：`ecall from U-mode`，推进 `epc += 4` 后进入 `syscall_dispatch`。
- 非法指令：打印错误并结束进程。
- 页错误：打印 `scause`、`epc`、`stval` 并结束进程。
- 定时器中断：已分类，当前教学版默认不启用抢占。

系统调用号定义在 `include/syscall.h`。已实现：

```text
SYS_write
SYS_exit
SYS_getpid
SYS_yield
SYS_fork
SYS_wait
SYS_exec
SYS_readfile
SYS_info
```

用户程序通过 `user/syscall.c` 中的内联汇编把参数放入 `a0` 至 `a5`，把系统调用号放入 `a7`，再执行 `ecall`。

## 7. 内存管理设计

物理内存布局采用 QEMU virt 常见布局：

```text
UART0     = 0x10000000
KERNBASE  = 0x80200000
PHYSTOP   = 0x88000000
PGSIZE    = 4096
```

物理页分配器位于 `kernel/kalloc.c`，使用单链表管理空闲页：

- `kinit`：从内核 `end` 到 `PHYSTOP` 建立空闲链表。
- `kalloc`：取出一页并清零。
- `kfree`：检查页对齐和地址范围后归还链表。

虚拟内存使用 RISC-V Sv39。`kernel/vm.c` 实现：

- `walk`：三级页表遍历，需要时分配中间页表页。
- `mappages`：建立虚拟地址到物理地址的页映射。
- `kvminit`：建立内核页表，映射 UART 和内核直接映射区域。
- `uvmcreate`：创建用户页表，并复制内核高地址根页表项。
- `uvmalloc` / `uvmfree`：分配和释放用户页。
- `copyin` / `copyout` / `copyinstr`：在内核和用户地址空间之间复制数据。

用户程序运行在低地址空间，用户页设置 `PTE_U`。内核映射不设置 `PTE_U`，因此用户态不能直接读写内核。trap 后 CPU 进入 S-mode，内核可以使用同一页表短暂保存现场，然后切换回完整内核页表。

## 8. 进程管理与调度设计

进程结构体 `struct proc` 定义在 `include/proc.h`，包含：

```text
pid
state
kernel stack
user page table
trapframe
context
parent
exit status
name
```

进程状态包括：

```text
UNUSED USED RUNNABLE RUNNING SLEEPING ZOMBIE
```

调度器位于 `kernel/proc.c`，上下文切换汇编位于 `kernel/swtch.S`。ToyOS 当前采用协作式调度：用户进程通过 `SYS_yield` 主动让出 CPU，`fork/wait/exit` 内部也会调用调度器。`swtch` 保存和恢复 RISC-V callee-saved 寄存器，包括 `ra`、`sp` 和 `s0` 至 `s11`。

关键接口：

- `procinit`：初始化进程表。
- `allocproc`：分配进程、内核栈和 trapframe。
- `userinit`：创建第一个用户进程 `init`。
- `scheduler`：寻找 `RUNNABLE` 进程并切换运行。
- `fork`：复制父进程用户页表和 trapframe，子进程返回值为 0。
- `exit`：设置退出状态并进入 `ZOMBIE`。
- `wait`：回收僵尸子进程。
- `exec`：从内核内嵌用户 ELF 表加载新程序。

## 9. ToyFS 文件系统设计

ToyFS 位于 `kernel/fs.c`，是只读内存文件系统。它不实现磁盘块、inode 位图、目录写入或缓存，而是用静态表保存路径和内容：

```text
/hello.txt -> Hello from ToyFS!
```

系统调用 `SYS_readfile` 完成路径字符串复制、ToyFS 查找、内容读取和 `copyout`。用户程序 `cat` 调用：

```c
readfile("/hello.txt", buf, sizeof(buf) - 1)
```

ToyFS 演示了真实文件系统中的三个核心抽象：路径查找、文件内容字节流和用户态读文件接口。它与真实文件系统的区别是没有块设备、持久化、目录树修改、权限控制和缓存一致性。

## 10. 用户程序与 Shell

用户程序位于 `user/`：

- `init.c`：第一个用户进程，执行 `exec("sh")`。
- `sh.c`：脚本式 shell，支持 `help`、`hello`、`forkdemo`、`cat hello.txt`、`ps/info`、`exit`。
- `hello.c`：测试 `write`、`getpid`、`yield`。
- `forkdemo.c`：测试 `fork`、`wait`、父子进程输出。
- `cat.c`：测试 ToyFS 的 `/hello.txt`。

为了降低文件系统和 ELF 查找复杂度，ToyOS 把用户 ELF 通过 `kernel/userbins.S` 内嵌到内核。`exec` 根据程序名在静态表中查找 ELF 并装入用户页表。这是教学简化，不代表真实系统的磁盘可执行文件加载流程。

## 12. 遇到的问题与解决方案

问题一：trap 后页表不会自动切换。

解决方案：用户页表复制内核高地址 root 映射，但不设置 `PTE_U`。这样用户不能访问内核，S-mode trap 入口却可以在用户页表下保存现场，再切换到内核页表。

问题二：完整文件系统和完整 ELF/磁盘加载工作量较大。

解决方案：保留 ELF 加载逻辑，但把用户 ELF 内嵌到内核静态表。文件系统使用 ToyFS 只读内存表，专注演示路径查找和读文件系统调用。

问题三：抢占式调度需要可靠的 timer interrupt 配置和中断嵌套处理。

解决方案：当前版本采用协作式调度，通过 `yield`、`wait`、`exit` 展示调度和上下文切换；trap 中保留 timer interrupt 分类，后续可扩展为抢占式。

问题四：当前 Windows 环境缺少构建工具。

解决方案：源码工程完整生成，并提供 `scripts/check_env.sh`、README 中的 WSL2/Ubuntu 安装步骤和 `make test` 标准验证流程。

## 13. 实验总结

本实验实现了一个可编译、可运行、可展示的教学型 RISC-V 小操作系统。系统从 OpenSBI 进入内核，完成串口输出、trap、页表、物理页分配、进程调度和 ToyFS 初始化，然后进入用户态运行 shell 和多个用户程序。

通过本实验可以清楚观察到：用户程序并不直接调用内核函数，而是通过 `ecall` 触发 trap；内核通过 trapframe 保存用户现场，通过页表权限实现基本隔离；进程切换本质上是内核上下文和用户地址空间的配合；文件系统可以先用简单内存表展示路径与文件内容抽象，再逐步替换为真实块设备文件系统。

后续如果继续提高完成度，可以加入 UART 交互输入、抢占式 timer 调度、文件描述符表、可写 ToyFS、真实 ramdisk 块层、管道、更多异常测试和更完整的用户态 C 库。
